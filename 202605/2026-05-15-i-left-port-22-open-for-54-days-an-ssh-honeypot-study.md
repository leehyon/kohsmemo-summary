## TL;DR
基于 SSH 蜜罐实验，揭示公网服务面临持续自动化扫描与爆破攻击，多数为低级脚本，少数为高阶攻击者；同时指出弱口令与加密节点为主要目标，并强调基础安全防护的重要性。

## Summary
### 核心主题
- 基于 SSH 蜜罐（ honeypot ）的实证研究，揭示公网暴露服务的真实攻击生态
- 展示自动化攻击规模、行为模式及攻击者分层（脚本化 vs 专业化）
- 强调互联网“持续扫描 + 弱口令利用”的常态化威胁

### 实验设计与环境
- 构建模拟 Ubuntu 22.04 的 SSH 服务（ Python + paramiko ）
- 接受所有密码，提供伪 shell 与文件系统，记录完整行为日志
- 部署方式： Docker 容器，暴露 22 端口，持续运行 54 天
- 日志规模：317 MB，结构化 JSON 记录

### 攻击即时性与背景噪声
- 上线 1 分钟内即被扫描并尝试登录
- 本质为全球持续自动化扫描（ background radiation ）
- 结论：任何暴露端口会被“立即发现”，非定向攻击

### 规模与频率
- 日均约 4,987 次连接（约 3.5 次 / 分钟）
- 持续全天候无间断攻击
- 峰值：单日约 23,000 次（≈16 次 / 分钟）

### 登录凭据特征
- 总尝试：255,566 次，涉及 48,102 个密码
- 常见弱密码：
  - 123456（>10%）
- 特征行为：
  - IoT 默认凭据（如 3245gs5662d34）频繁出现 → 固件内置
  - 针对 Solana 节点的凭据（ sol / solana / validator ）
- 结论：攻击具有明确资产目标（如区块链节点）

### 攻击行为模式（登录后）
- 99.6% 为自动化攻击：
  - 不进入交互 shell，仅执行单条命令
  - 常见命令：
    - uname（系统指纹识别）
    - echo（存活检测）
    - chattr（准备持久化）
- 攻击流程：
  1. 指纹识别（ fingerprinting ）
  2. 判断目标价值
  3. 后续再投递 payload

### 流量时间分布
- 高峰：01:00–04:00 UTC
- 低谷：07:00–09:00 UTC
- 周期性：周末与周一更活跃
- 原因：C2 基础设施地区活跃时间差异

### 来源分析
- 总 IP：7,556
- 类型分布：
  - 云 / VPS：52% IP，产生 59% 流量
  - 住宅 / IoT：48% IP，分布更广
- 地理分布：
  - 来源遍布全球
  - 热点城市：悉尼、阿姆斯特丹、法兰克福（云资源集中）
- 特殊现象：
  - 单一比利时 IP：15.6 万次尝试（持续高频攻击）
- 结论：
  - 多数攻击来自“被滥用的基础设施”，而非真实攻击者位置

### 攻击来源结构（集中度）
- 单一云服务商：47% 流量
- 前五来源：69% 流量
- 长尾：少量单节点贡献大量攻击（ compromised devices ）

### 少数人工攻击（0.4%）
- 行为特征：
  - 输入命令、出现 typo、探索文件系统
- 分类：
  - 初学者型：探索系统（如安装 neofetch）
  - 反取证型：
    - 清除 bash 历史（ HISTFILE 操作）
  - 专业攻击者：
    - 使用 /dev/tcp 下载 payload
    - 多 C2 节点轮换
    - 使用 UPX 压缩二进制
  - IoT bot：
    - 模拟路由器 CLI（ enable / system ）
    - 部署 Mirai 变种
- 结论：
  - 攻击者能力差异极大（脚本小子 vs 专业组织）

### 攻击技术特征
- 自动化 botnet：
  - 基于默认凭据爆破
  - 扫描 + 分类
- 专业攻击：
  - 无文件下载工具（避免检测）
  - 自定义 payload 与加密参数
  - 持久化与隐蔽性设计
- IoT botnet：
  - 多协议下载（ wget / curl / tftp ）
  - 自删除 + 标记感染

### 关键发现与结论
- 互联网环境：
  - 高频噪声扫描是常态
- 攻击构成：
  - 绝大多数为自动化脚本
  - 少量高水平攻击者威胁更大
- 资产偏好：
  - 加密货币节点为高价值目标
- 人类行为：
  - 存在“非恶意探索者”
- 安全认知：
  - 攻击并非“针对个体”，而是“系统性扫描”

### 安全建议
- 使用密钥认证（ key-based authentication ）
- 禁用密码登录
- 更换默认端口（避免低成本扫描命中）
- 减少暴露面
- 对公网服务保持“默认被攻击”的假设

### 方法论价值
- 蜜罐可用于：
  - 收集真实攻击数据
  - 理解攻击链和行为模式
  - 安全策略验证（ red team / blue team ）
- 低成本实现（单文件 Python + Docker）即可获取高价值数据
