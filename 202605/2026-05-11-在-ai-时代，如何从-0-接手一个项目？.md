# 在 AI 时代，如何从 0 接手一个项目？

- Added: 2026-05-11 05:00:42

## TL;DR
文章强调 AI 时代坚持实事求是，以软件工程和业务逻辑为核心，AI 仅作辅助。提出接手项目的务实四步法，并针对神经多样性及心理障碍群体提供生存策略。

## Summary
**核心主题**
在 AI 时代，强调“实事求是”的实践精神，结合软件工程原理，提出一套从零接手现有项目的务实方法论；主张业务逻辑是护城河，软件工程是基石，AI 仅作为提升下限的辅助工具，并针对神经多样性及心理障碍群体提供特定的生存策略。

**关键信息**
*   **现实背景与认知偏差**：
    *   网上 AI 编程教程多为“氛围编程”或玩具项目，脱离实际生产环境。
    *   企业招聘需求主要为维护现有系统（接手项目），而非从零开发。
    *   人的认识来源于生产实践，脱离生产环境的技术分享华而不实。
*   **核心观念**：
    *   业务逻辑是真正的护城河，软件工程是托底基石。
    *   AI 的上限取决于人的上限，懂业务和工程才能驾驭 AI。
*   **接手项目的四步法**：
    1.  **先看数据库**：数据库表结构承载了核心业务逻辑和商业机密。利用 SQL 建表语句理解字段含义与表关系，必要时向业务方求证，不可将数据库结构上传至公网 AI。
    2.  **罗列 API 接口**：分析 Controller 层代码，利用 AI 生成 API 接口文档。明确系统能提供的业务能力，作为后续与 AI 协作的重要上下文。
    3.  **查看配置文件**：分析 `pom.xml`、`application.yml` 等文件，利用 AI 提炼项目技术栈及版本号。解决版本兼容性问题，并为 AI 提供项目规则上下文。
    4.  **还原核心业务逻辑**：阅读 Service 层代码，利用 AI 追踪特定业务流程或生成需求规格说明书、流程图。AI 可辅助理解显式逻辑，但无法替代人发现隐式 Bug、性能隐患或系统缺失。
*   **特殊群体的应对策略**：
    *   **自闭症谱系（ASD）与 ADHD**：
        *   **看数据库**：ASD 利用结构化优势但需防止过载，利用可视化图谱辅助；ADHD 需降低注意力门槛，设置多巴胺奖励。
        *   **社交障碍**：采用“先问 AI 再问人”策略，准备标准化话术，优先书面异步沟通，记录“理解偏差案例”。
        *   **还原逻辑**：ASD 需让 AI 显式化隐藏的 `if/else` 规则，使用红绿灯清单；ADHD 需将长流程拆解为短流程，利用 Mermaid 流程图作为“外挂大脑”。
    *   **抑郁症与焦虑症**：
        *   **抑郁症**：核心是意义感丧失和精神运动性迟滞。策略是大幅降低执行门槛（如仅以“开机”为目标），禁止自我攻击，接受自己是病人的客观现实。
        *   **焦虑症**：核心是灾难化思维和完美主义。策略是接受 Bug 和未知的存在，信任 AI 的纠错能力，打破分析瘫痪。

**逻辑脉络**
1.  **破题立论**：指出当前 AI 编程分享脱离实际，强调接手项目比从零开发更普遍，引出马克思主义“实践论”作为哲学基础。
2.  **原理阐述**：通过软件生命周期和团队角色说明项目复杂性，指出业务逻辑的重要性及 AI 的局限性，确立“人主导，AI 辅助”的原则。
3.  **方法论构建**：详细展开“看数据库 -> 罗列 API -> 看配置 -> 还原逻辑”的四步法，每一步包含具体操作、目的及 AI 提示词示例。
4.  **差异化适配**：针对 ASD、ADHD、抑郁症、焦虑症患者的具体生理和心理障碍，对四步法进行拆解，提供定制化的减负和增效策略。
5.  **总结升华**：回归“实事求是”的核心，强调业务与工程的重要性，鼓励不同人群在 AI 时代利用工具但保持人的主导地位。
