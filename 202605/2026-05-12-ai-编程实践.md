## TL;DR
文章旨在通过绑定核心工具、Git 管理配置及构建分层技能体系，打造标准化的 AI 编程“数字分身”工作流，在提升生产力的同时严控交付质量。

## Summary
核心主题: 构建 AI 编程的确定性工作流与“数字分身”，通过标准化配置与技能体系实现生产力跃升。

逻辑脉络: 从早期的工具试错与焦虑，过渡到选定核心 Agent，进而建立标准化的配置仓库与技能库，通过持续迭代形成人机默契的协作模式，最终实现个人生产力的高度可复制。

关键信息:

1.  **深度绑定核心工具**
    优先选择 Codex 或 Claude 等头部模型，建议官方订阅。通过深度阅读文档与自定义配置，磨炼出最顺手的工具，避免在众多平庸工具间频繁切换。

2.  **配置管理 Git 化**
    创建私有的 `.agents` 仓库，利用 Git 同步配置。通过 Makefile 和软链接将差异化配置（如 skills、AGENTS.md）映射到不同 Agent 的目录下，实现跨机器体验的一致性。

3.  **固化交互协议**
    建立 `AGENTS.md` 文件，明确沟通语气、指令规则及常见错误处理方式。将其软链接至 Agent 指定目录，作为与 AI 交互的“宪法”，在使用中持续迭代。

4.  **构建分层技能体系**
    *   基础层: 引入 `superpowers` 等轻量级、原子化的工作流作为底层支撑。
    *   原子层: 筛选符合个人编码风格的原子 Skill（如 code-review），通过 Git submodule 纳入管理。
    *   定制层: 利用 `$skill-creator` 基于底层 Skill 组合（如重构流程）或分析历史对话模式，创建专属上层 Skill，将繁琐的日常行为自动化。

5.  **CLI 能力扩展**
    偏好 CLI + Skills 模式而非 MCP，通过集成各类 CLI 工具（如 playwright-cli）来扩展 Agent 的操作边界与能力。

6.  **持续迭代与进化**
    将 Agent 配置、Skills 及 CLI 视作一个可进化的系统。不断优化触发规则、淘汰低效工具，打造一套可移植、高默契的工作流，即“数字的你”。

7.  **严控交付质量**
    警惕 AI 幻觉与模型差异，不可完全信赖 AI 生成的代码。利用 AI 提升测试覆盖率与调试速度，但必须坚持人工 Code Review 和自测，确保代码在掌控范围内。
