# 把 LLM 当成“人”，才是 Agent 工程进阶的起点

## TL;DR
本文主张 LLM Agent 进阶关键在于将 LLM 视为具备人类认知特征的合作伙伴。通过模拟人类记忆与视觉感知，结合原生工具与闭环反馈，以拟人化设计替代机械控制，构建健壮高效的 Agent 系统。

## Summary
**核心主题**
本文主张 LLM Agent 工程进阶的关键在于将 LLM 视为具备人类认知特征的“合作伙伴”，而非单纯的输入输出机器；通过顺应人类的心理认知习惯、工作流及感知方式来设计系统架构，能显著提升 Agent 的效能与准确性。

**关键信息与逻辑脉络**

1.  **认知对齐：构建“技术实习生”思维模型**
    *   **逻辑**：传统面向代码编程习惯于绝对指令，但 LLM 虽拥有无限理论知识，却对具体业务上下文一无所知。
    *   **实践**：不应只给模糊的单句 Prompt，而应像对待实习生一样，为 Agent 提供详尽的“工作手册”、业务背景和执行标准，帮助其锚定需求。

2.  **记忆解耦：模拟人类工作记忆与长期记忆**
    *   **逻辑**：人类工作记忆容量有限，主要依靠注意力焦点，仅在需要时查阅外部资料，而非背诵所有文档。
    *   **实践**：避免将海量文档直接塞入 LLM 上下文窗口。应进行“认知卸载”，将核心信息保留在上下文（工作记忆），将海量数据存储于 Vector DB（长期记忆），通过 Top-K 检索按需唤醒，避免噪声干扰。

3.  **感知层革新：视觉感知优于结构化数据**
    *   **逻辑**：在 UI 测试或 Web 开发中，DOM 树等结构化文本充斥噪声且难以映射最终样式；人类调试依赖视觉观察，而非阅读源码。
    *   **实践**：利用多模态能力，优先让 Agent 查看页面截图（如通过 Playwright），以“所见即所得”的视觉模式进行理解和操作，而非解析复杂的 DOM 节点。

4.  **工具生态：顺应“原生职业习惯”**
    *   **逻辑**：顶尖 LLM 经海量代码语料训练，天生具备“程序员职业常识”。
    *   **实践**：提供人类程序员熟悉的原生工具（如 Bash、Git、Markdown），而非自创复杂的自定义 Function Call。保持工具链的跨平台统一性（如在 Windows 使用 Git Bash），以激发模型的原生代码能力。

5.  **行动与反馈：构建容错的“闭环试验场”**
    *   **逻辑**：依据熵增理论，孤立运行的 Agent 最终会陷入幻觉；人类通过“编写-报错-修正”的闭环保证质量。
    *   **实践**：建立强大的 Harness 工程作为“硬门禁”，自动运行 Linter、Compiler 和单元测试，捕获错误日志并反馈给 Agent，强制其进行自我反思与修正。

6.  **先谋后动：引入 SDD 规避盲目操作**
    *   **逻辑**：低效开发往往是“拿来就写”，导致代码耦合度高；资深人类架构师遵循“先规划后编码”的原则。
    *   **实践**：强制实施 SDD（Spec-Driven Development），在动手写代码前先生成规格说明、计划和任务列表，并结合 TDD（测试驱动开发），将 Agent 的思维模式从直觉式的“快思考”转变为逻辑严密的“慢思考”。

**总结**
Agent 工程的高阶范式在于放弃对 LLM 的机械式控制，转而通过拟人化的设计——赋予其视觉、科学的记忆管理、熟悉的工具、严格的环境反馈以及规范的规划流程——来激发其潜能，这才是构建 robust Agent 系统的必经之路。
