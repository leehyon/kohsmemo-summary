## TL;DR
本文探讨如何将 AI 经验转化为个人资产。通过 SumSec-Skills 利用 Git 结构化定义 Skill，实现技能的自我进化与跨平台复用，从而摆脱对特定工具的依赖。

## Summary
**核心主题**
在 AI 模型日益普及且工具快速迭代的背景下，探讨如何将个人使用 AI 的经验转化为可积累、跨平台、能自我进化的核心资产，从而摆脱对特定公司或平台的依赖。

**关键信息**
*   **项目定位**：SumSec-Skills 是一个基于 Git 仓库的 AI 技能库，旨在将“教 AI”的经验（Prompt、规则、工作流）结构化、版本化，使其成为个人独有的、可随身携带的技能资产。
*   **Skill 定义**：Skill 不仅仅是 Prompt，而是包含“结构化行为规范 + 参考资料 + 辅助脚本”的完整能力包，定义了 AI 在特定场景下的思考、决策与行动逻辑。
*   **架构设计原则**：
    *   **Plugin 化分类**：按领域（如 `writing-zh`、`dev-tools`）拆分为独立 Plugin，以节省 AI 上下文注意力、适应不同更新节奏，并支持用户按需安装。
    *   **多平台分发**：核心内容（`SKILL.md`）仅维护一份，通过外层包装各平台的 manifest（适配 Cursor、Claude 等），实现一次编写、到处运行，避免工具锁定。
    *   **开放同步机制**：利用 Git Submodule 嵌入官方仓库（如 `claude-plugins-official`），确保个人技能始终基于最新的平台规范与功能。
    *   **自我进化能力**：通过集中化管理，利用 AI 工具（如 `skill-optimizer`）审计技能质量，并通过 Git 记录演进历程，实现系统性优化。

**逻辑脉络**
1.  **现实困境**：指出职场环境与 AI 工具的不确定性（换公司、换工具），以及用户在不同场景下重复“教” AI 的低效问题，强调唯有结构化的经验才是真正属于个人的资产。
2.  **核心理念**：提出将分散的 Prompt 升级为具有行为规范属性的 Skill，解决“教一次，到处用”的问题。
3.  **设计思考**：
    *   **分类管理**：阐述为何将技能库拆分为多个 Plugin（基于注意力限制、更新频率差异及用户认知习惯）。
    *   **跨平台策略**：通过核心内容与适配层分离的设计，打破单一平台锁定，确保技能资产的归属权。
    *   **持续迭代**：利用 Submodule 跟踪上游官方更新，保证技能库不过时；利用集中化优势进行数据分析与自我优化。
4.  **价值愿景**：总结“渐进式加载”的设计哲学，并展望未来——模型将成为公共基础设施，个人构建的 Skill 库深度将是真正的核心竞争力。
