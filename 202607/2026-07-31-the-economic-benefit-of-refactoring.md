# The Economic Benefit of Refactoring
- URL: https://martinfowler.com/articles/exploring-gen-ai/refactoring-economic-benefit.html
- Added: 2026-07-31 09:03:58
- Tags: #engineering

## TL;DR
实验表明，重构 AI 生成的代码可将后续智能体修改的输入 token 消耗降低 83%，虽重构过程需人工指导，但长期经济收益明确。

## Summary
作者通过一个由 AI 智能体编写的 150,000 行代码应用，设计实验验证重构能否降低后续智能体修改代码的 token 消耗。实验对单个 17,155 行的数据访问层文件进行 15 步严格重构，发现相同功能变更的输入 token 从 159,564 降至 27,360，节省 83%，证明重构具有显著经济价值。

**逻辑脉络**
- 背景：AI 智能体生成的代码缺乏去重和抽象，导致单个文件膨胀至 17,155 行，成为重构靶点。
- 方法：用固定 prompt 让全新智能体执行同一代表性子任务，记录每步重构后的 token 消耗，排除学习效应。
- 结果：输入 token 在文件拆解后急剧下降，总代码量基本不变，说明节省源于智能体读取更少的文件。
- 局限：重构本身耗时不菲，且 Claude 对重构的策划与执行能力有限，需要人工引导。

**底层逻辑**
- 核心假设：智能体的 token 成本主要来自读取代码，而非生成代码；重构通过改善代码结构，让智能体更快定位相关部分。
- 遵循严格重构纪律（Martin Fowler 定义），每次改动保持行为不变，分步验证。

**Takeaways**
- 重构可将后续智能体修改的输入 token 减少 83%，按 Sonnet 5 定价单次节省 39.7 美分，长期收益显著。
- 节省的关键并非减少代码总量，而是让智能体能够识别并只读取必要文件，随机拆分文件无效。
- 输出 token 几乎不受重构影响，因为代码生成量变化不大，但输入端的节省已足够可观。
- Claude 在重构上表现不佳：计划需人工修正（错过最有价值步骤），执行依赖 grep/sed 脚本，且容易出错。
- 实验是单一开发者、绿地项目的初步探索，未来需研究更复杂变更、全局重构及不同重构策略的性价比。
