# Design Patterns Suck
- URL: https://luminousmen.com/post/design-patterns-suck/
- Added: 2026-07-03 02:43:04
- Tags: #design

## TL;DR
设计模式是语言缺陷的变通方案，多数模式在高级语言中消失；其唯一价值是沟通术语，不应作为设计教条。

## Summary
文章强烈批判设计模式，认为其被过度推崇，本质上是语言缺陷的变通方案，常导致过度工程化。作者以 Java 为例，指出其冗长语法迫使开发者使用大量模式，而在表达力更强的语言（如 Python、Scala）中多数模式自然消失。模式唯一真正的价值是作为团队沟通的术语，而非设计指南。

**逻辑脉络**
- 从设计模式起源（GoF 书）切入，指出其被神化为教条。
- 对比 Java 与 Scala/Python：Java 的 Singleton 需十几行代码，Scala 用 `object` 一行解决；Factory、Observer 等在高级语言中成为语言特性。
- 批评设计模式催生过度工程：开发者盲目套用模式，导致代码复杂难懂。
- 阐述模式的实际作用：仅为命名约定，方便交流；优秀开发者靠基础原则（如关注点分离）自然写出好代码。
- 引用 James Gosling（Java）与 Guido van Rossum（Python）的设计哲学差异：前者不信任开发者，后者信任并给予灵活工具。

**底层逻辑**
- 核心假设：设计模式是语言不完善的产物；语言越强大，需要的模式越少。
- 方法论：评估模式成本与收益，反对为模式而模式；主张优先用语言原生特性解决问题。

**Takeaways**
- 设计模式是语言缺陷的补丁，不是设计智慧的体现。
- 多数模式在表达力强的语言中消失（如 Python 的模块即 Singleton）。
- 过度使用模式导致代码臃肿、难以维护；简单直接往往更好。
- 模式的真实价值是术语简写，便于团队沟通，不应作为设计模板。
- 提升语言能力（如学习 Python、Scala）可自然减少对模式的依赖。
