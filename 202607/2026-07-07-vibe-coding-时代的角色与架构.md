# Vibe Coding 时代的角色与架构
- URL: https://roriri.one/2026/07/04/vibe-coding
- Added: 2026-07-07 05:34:31
- Tags: #agent #vibe-coding

## TL;DR
Vibe Coding 无法替代人类在产品研发中的核心作用。文章指出，快速代码输出会加速架构腐化，只有通过严谨的流程和人类对问题的深刻理解，才能维持工程可持续性。人类的价值在于提出好问题、把控方向。

## Summary
文章批判了 Vibe Coding 时代各角色（产品、设计、工程师）认为 AI 能替代他人的错觉，指出软件研发如同建大楼，需求变更和快速代码输出会加速架构腐化。作者强调，只有通过严谨的流程——从用户画像、Epic、User Story、Job Story 到 Journey Map，再到架构设计和测试——才能维持工程可持续性。人类不可替代的价值在于提出好问题、把控设计方向，而 LLM 缺乏共情和责任感。

**逻辑脉络**
- 现象：Vibe Coding 让各角色误以为自己能独立完成产品，导致项目失败。
- 本质：开发是分层依赖的，快速输出和思考缺失导致架构劣化，不可维护。
- 解决方案：必须遵循从用户研究到架构设计的完整流程，每层都需清晰定义。
- 结论：人类优势在于定义问题、管理质量，LLM 只能作为辅助工具。

**底层逻辑**
- 第一性原理：软件产品的质量和可持续性取决于问题空间与方案空间的有序衔接，任何跳过思考的行为都会造成工程腐化。
- 核心假设：LLM 没有真实生活体验，无法共情或承担责任，因此不能替代人类在定义和决策中的角色。

**Takeaways**
- Vibe Coding 加速架构腐化，省下的时间应投入架构维护和测试。
- 产品研发必须遵循从用户研究到架构设计的顺序流程，不可跳过。
- 人类的核心竞争力是提出好问题（用户问题、架构问题）并掌控设计方向。
- 用规则（如 Linter、测试）和文档体系约束 LLM 输出，减少重复和错误。
- LLM 缺乏共情和责任感，必须由人类最终负责项目成败。
