# Don't you mean extinct?

- Added: 2026-07-14 07:50:30

## TL;DR
以《侏罗纪公园》特效师 Phil Tippett 的“灭绝”轶事类比程序员对 LLM 的焦虑，强调应主动学习 LLM 原理、优化编码与审查流程、拥抱工具进化，从而像 Tippett 一样转型而非被淘汰。

## Summary
文章以《侏罗纪公园》中停格动画大师 Phil Tippett 面对 CGI 革命时感叹“我灭绝了”的轶事为引，类比当前程序员对 LLM 取代自身工作的焦虑。作者认为避免被淘汰的关键在于进化：主动学习 LLM 的工作原理与使用技巧，将 LLM 视为工具而非威胁，并调整开发实践以提升效率与代码质量。

**底层逻辑**
- 技术的代际更迭是常态，每次革命都会淘汰不愿适应的人，但也会创造新的工作机会。真正的核心竞争力是解决问题的能力，而非具体编程语言或工具。
- LLM 是又一波浪潮，如同 90 年代网页、00 年代移动端一样，需要“驾驭浪潮”而非抗拒。

**Takeaways**
- **主动学习 LLM 原理**：推荐 Andrej Karpathy 的视频和 Sebastian Raschka 的书籍，从底层理解模型运行机制。
- **调整编码方式**：不再手写每一行代码，但需保持代码质量和架构理解。通过 `GEMINI.md`/`CLAUDE.md` 文件定义编码规范，让 LLM 模仿个人风格。
- **提高代码审查标准**：
  - 要求更规范的 commit 消息、更清晰的代码结构、更小的 PR 粒度。
  - 利用 LLM 自动进行初轮审查，并要求为每个 PR 编写单元测试。
  - 减少外部依赖，鼓励自行实现简单功能。
- **团队小型化**：借助 LLM 能以更小团队完成更多工作，甚至复活个人项目。
- **与 LLM 生态共进**：研究 llama-cpp、ollama 等开源项目，利用 LLM 辅助阅读论文和代码库。
- **从历史中汲取动力**：Phil Tippett 并未被淘汰，而是适应新工具（Dinosaur Input Device）并赢得奥斯卡。个人应找到学习动机，避免被恐慌驱使。
