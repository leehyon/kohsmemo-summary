# The Insanity of Being a Software Engineer
- URL: https://0x1.pt/2025/04/06/the-insanity-of-being-a-software-engineer/
- Added: 2026-07-24 02:14:09

## TL;DR
软件工程师被期望掌握从编程到 DevOps 到管理的无尽技能，行业失去了专业化，或许 AI 能带来改变。

## Summary
文章指出，软件工程师面临越来越离谱的技能要求，从多种编程语言、框架到 DevOps 再到管理，几乎无所不包。作者从自身经历出发，描述了行业对“全栈”的执念以及专业化消失的困境，最终质疑这种趋势的合理性，并认为 AI 辅助开发或许是一条出路。

**逻辑脉络**
- 开篇点题：软件工程师需要掌握多种语言和框架，但公司往往期待你立即上手特定技术栈如 Rails、Django、Laravel，以及 CSS 和 JavaScript。
- 随着 React 兴起，公司不愿招更多工程师，于是“全栈”诞生，你必须学会 React、REST API，再加上 TypeScript、Redux 等工具链。
- 如果你坚持旧方式，会发现自己与行业脱节，难以培训只懂 React 的新人。
- 随后 DevOps 取代系统管理员，你需要 Docker、Ansible、AWS、Terraform 等，即使你的应用只是一个静态二进制文件。
- 晋升经理后还要学习管理等全新技能，但公司可能不增员，导致你仍要写代码。
- 举例：某神秘公司要求 Senior 级别掌握 Rails、Hotwire 以及原生移动开发，讽刺技能要求无上限。
- 结尾：软件日益复杂确有原因，但为什么不能像盖房子那样分工协作？AI 用提示词构建应用或许不是坏事。

**Takeaways**
- 软件工程师被期望掌握从前端到后端、DevOps 到管理的全栈技能，学习负担极重。
- 行业缺乏专业化分工，与建筑等传统行业形成鲜明对比。
- 这种“全栈”趋势导致人才身心俱疲，且效率未必更高。
- AI 辅助开发可能改变现状，让工程师从复杂工具链中解放出来。
