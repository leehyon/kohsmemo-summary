# The Human-in-the-Loop is Tired
- URL: https://pydantic.dev/articles/the-human-in-the-loop-is-tired
- Added: 2026-07-23 08:45:27
- Tags: #agent

## TL;DR
LLM 辅助编程提高了产出，却加重了监督负担，降低了工作满意度。开发者陷入“奖励函数断裂”的疲劳中，核心技能转向品味与判断，团队需主动对抗孤独感。

## Summary
文章探讨了 LLM 辅助编程带来的矛盾：生产效率显著提升，但开发者的疲劳感、孤独感和满意度下降也随之加剧。作者认为，瓶颈从来不是代码生成，而是人类的注意力与判断力，并提出需要将这种“反馈循环断裂”视为工程问题来修复。

**逻辑脉络**
- 编程曾带来“掌控宇宙”的创造快感，而 LLM 自动化了部分工作，却将人的角色转变为监督者。
- 以同事 Douwe 为例：每天面对大量 AI 生成的 PR，审查负担沉重，且失去了与人协作的学习乐趣。
- “强度陷阱”：AI 让人同时启动更多任务，但深思熟虑的完成能力未变，导致持续疲劳。
- 引入“人类奖励函数问题”：手写代码的微小奖励（如解决问题、编译成功）被监督的认知负荷取代，反馈回路被破坏。
- 编程变得更孤立：与机器的反复交互取代了与同事的自然沟通，且这种不确定的奖励机制具有成瘾性。
- 类比响应式设计过渡：技能并未消失，而是从像素级控制转向系统性思维；核心品味与判断力愈发重要。

**Takeaways**
- LLM 使开发者从代码生产者变为质量把关者，但监督工作的重复性与低奖励导致“人类在回路但疲惫不堪”。
- 核心价值转向品味、细微判断、架构见解等人类专长，高质量指导 LLM 依赖深度领域知识。
- 新技能涌现：如对计划做“事前验尸”、从历史审查中提取规则写入 `AGENTS.md`，将隐性知识显式化。
- 任务并行性增加，但完成能力不变，需警惕“开始很多、完成很少”的虚假生产力。
- 团队需主动维护协作文化，避免因过度依赖 AI 而导致人际疏离。
