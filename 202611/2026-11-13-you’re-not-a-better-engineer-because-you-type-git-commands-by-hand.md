# You’re Not a Better Engineer Because You Type Git Commands by Hand
- URL: https://minid.net/2026/7/10/ai-works-for-me
- Added: 2026-11-13 02:27:52

## TL;DR
作者主张把提交信息、PR 描述、注释、命名、Git/Issue 管理和发布检查交给 AI agents；关键不是放弃理解，而是自动化重复执行，把时间留给架构判断、审查与责任。

## Summary
作者以 27 年编程经验说明：自己已把提交信息、PR 描述、代码注释、命名规范、Git 分支管理、Issue 跟踪与发布流程等琐碎工程开销交给 AI agents。核心观点不是放弃理解，而是把重复执行自动化，把精力留给架构决策、审查与交付责任。

**逻辑脉络**
- 先列举开发者厌恶且耗时的小任务，说明 AI 在提交信息、PR 描述、注释规范上更一致。
- 再扩展到命名、分支创建、PR/Issue 管理，以及用 `/definition-of-done`、`/pr-check-release` 等技能完成交付检查。
- 最后指出这些微小任务乘以每个工程师、每次提交与发布，会消耗大量时间与金钱。

**底层逻辑**
- AI 擅长重复、机械、上下文密集但低创造性的工作。
- 人仍需理解底层机制，才能安全自动化、检查结果并识别错误。
- 自动化的是执行，不是理解或责任。

**Takeaways**
- 把提交、PR、注释、命名和 Git 卫生交给 AI，可减少不一致与遗忘。
- agents 能串起改名、改引用、跑测试、更新任务等完整闭环，而非单点操作。
- 用技能化检查清单管理 Definition of Done、发布与合并，降低仪式性开销。
- 省下的不是几分钟，而是重复在每次提交、分支错误、过期描述上的成百上千小时。
- 保留系统理解、架构判断、代码审查与最终责任，API 不可用时也能回到手工流程。
