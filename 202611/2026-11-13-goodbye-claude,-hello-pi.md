# Goodbye Claude, Hello Pi
- URL: https://caleb.software/posts/claude-to-pi.html
- Added: 2026-11-13 02:23:11

## TL;DR
作者因 Claude Code 在 IDE 集成、稳定性、功能堆叠和提示词膨胀上的长期问题，转而使用更极简、可定制的开源工具 Pi，并认为产品取舍比功能数量更重要。

## Summary
作者作为 Claude Code 长期用户，因长期积累的小挫折决定改用开源工具 Pi；文章既是迁移动因清单，也反思 AI 编码工具应如何做产品。核心矛盾在于 Anthropic 追求功能扩张与发布速度，牺牲了稳定性、可定制性和用户体验。

**逻辑脉络**
- 先承认 Claude Code 的开拓意义与个人使用历史，再以 AGENTS.md 支持滞后为例，说明其对用户成本不敏感。
- 列举 VSCode 集成只能单会话连接、官方 GUI 扩展问题多、子代理输出混乱等具体体验缺陷。
- 指出 Claude Code 高频发版、频繁改动系统提示与工具描述，且默认 Bash 工具描述冗长，带来稳定性与成本问题。
- 最后将问题归因于产品缺少愿景与“说不”的机制，并给出迁移 Pi 后的正面体验。

**Takeaways**
- 迁移主因不是能力不足，而是小摩擦累积：兼容性、IDE 集成、稳定性和可定制性。
- 功能军备竞赛未必提升个人开发者体验，反而增加认知与维护成本。
- 系统提示和工具描述频繁变动会显著影响模型表现，也造成 token 成本浪费。
- 产品团队需要有明确取舍和拒绝机制，否则易沦为功能堆叠。
- Pi 以极简、稳定和可扩展胜出；作者已为其编写扩展。
