# Code is clay now
- URL: https://www.albertodenia.com/writing/code-is-clay-now
- Added: 2026-10-21 01:22:46

## TL;DR
代理式编程让代码像黏土般可塑，变更成本骤降；但品味与架构仍关键。工匠模式留在循环中逐轮判断，工厂模式把判断前置到流水线，二者应按问题混用。

## Summary
文章认为，代理式编程让代码从难以修改的“石头”变成可塑的“黏土”：变更成本骤降，开发更像建模而非雕刻。但变更近乎免费不等于判断免费，品味、上下文、护栏与架构仍是作品成形的骨架和窑炉。

**底层逻辑**
- 代码底层材料未变，变的是修改成本；成本变化带来行为变化，可快速试形、整体推翻、从粗到细迭代。
- 判断力未被取代，只是位置变化：工匠在每轮循环中判断，工厂把判断前置到规格、生成器、验证器与护栏。
- 方法选择取决于问题：探索与体感用工匠模式，重复与规模化用工厂模式，真实工作常是混合。

**Takeaways**
- 把代码当黏土：先搭大形状，再中层特征，最后细节；可递归用于产品、功能、个人项目。
- 工匠模式让人留在快速反馈环中，适合探索想法、打磨需“感觉对”的功能；只判断界面是 vibe coding，也判断代码形态才是工程。
- 工厂模式把人移出循环，用规格、生成器、测试/评估/评审代理等构成可验证流水线，适合结构化代码库、重复模式和大量小任务。
- 两种模式都依赖人的判断，区别在施加时机；大产品需要工匠处理新问题，独立开发者也需工厂处理重复工作并扩展规模。
- 关键不是二选一，而是按问题选择合适方法，这正是软件工程一直以来的核心。
