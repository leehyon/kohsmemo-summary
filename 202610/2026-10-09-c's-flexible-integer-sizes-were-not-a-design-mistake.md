# C's Flexible Integer Sizes were Not a Design Mistake
- URL: https://pikuma.com/blog/c-integer-sizes-not-a-mistake
- Added: 2026-10-09 01:24:09

## TL;DR
int 从来不是 32 位的同义词。C 的整数宽度可变，是为了在 12 到 64 位字长、多种字符宽度与负数表示的机器上实现可移植与高效；强制固定尺寸会拖慢或无法实现。stdint.h 的精确宽度类型 C99 才出现且可选。

## Summary
文章反驳“C 的原生整数没有固定宽度是设计失误”这一常见看法：灵活的整数类型正是 C 在 12 至 64 位字长的世界里实现可移植性的手段。

**逻辑脉络**
- 现代机器 sizeof(int) 为 4，老 386 上为 2；原生类型不保证字节数，需用 <stdint.h> 取固定宽度。
- 批评者说这造成数十年移植 bug；但 C 诞生时计算机字长有 12、16、18、24、36、48、60、64 位，字符 6 至 9 位，负数有三种表示，部分机器不能按字节寻址。
- 源头是 BCPL 与 B 只有“机器字”一个类型；PDP-11 为字节寻址的 16 位机，B 的模型不匹配，于是 C 有了 char 与 int，int 即机器的自然整数。
- 1978 年 C 已运行于 16/32/36 位 int 与 8/9 位 char 的机器。
- 若强制 int 为 32 位：16 位机每次运算翻倍，36 位机需额外掩码，一的补码机需模拟，无 8 位字节的机器则无法定义 char。
- 因此 ANSI C 只保证最小范围，即 char 至少 8 位、short 和 int 至少 16 位、long 至少 32 位，由 <limits.h> 暴露；精确宽度类型到 C99 才出现且可选。

**底层逻辑**
- int 意为“该架构建议的自然大小”，从来不是 32 位。
- 可移植不等于固定尺寸，而是让每种实现以最廉价方式映射到自身硬件。
- 用最小范围保证加有符号溢出未定义，换取速度与跨机一致。

**Takeaways**
- 灵活整数尺寸是有意设计，不是疏忽。
- 固定 32 位会让 16/36 位机器变慢或需模拟。
- <stdint.h> 中只有 least/fast 类型是强制的，exact 类型可选。
- Lua 用 <limits.h>、CHAR_BIT 与范围检查写出可移植的 Clean C。
- 现代语言仍保留指针大小的原生整数；C23 才要求补码。
