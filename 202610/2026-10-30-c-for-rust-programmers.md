## TL;DR
文章从 Rust 视角梳理 C 的怪癖：布尔非原生、字符串以空字节结尾、整数宽度依平台、错误处理弱、数组退化为指针、无引用与借用检查，并提醒小心内存安全。

## Summary
作者以 Rust 程序员视角，梳理学习 C 时最反直觉的若干语言细节。全文不是 C 教程，而是提醒跨语言迁移时需注意的坑。

**逻辑脉络**
- 先说明写作动机：Rust 先行者缺少相关文章。
- 再按语言特性逐项对比：布尔、字符串、整数、错误处理、字段访问、数组、指针。
- 最后强调 C 把正确性责任交给程序员，内存错误会带来安全风险。

**底层逻辑**
- C 倾向最小抽象与信任程序员，少用类型系统表达约束。
- 许多设计是历史权衡，如空字符结尾字符串、平台相关整数宽度。
- Rust 用类型与编译器检查换取安全，C 则依赖约定与人工检查。

**Takeaways**
- 布尔在 C99 前靠 0/1，C23 前常需 stdbool.h，true/false 曾是宏。
- 字符串需预留并写入结尾空字节；空串也占 1 字节，中间空字节会破坏函数。
- 跨平台应使用 stdint.h 定宽整数；long 在 Unix 与 Windows 宽度不同。
- C 不强制处理错误，malloc 可能返回 NULL；数组传参退化为指针，sizeof 结果会变。
- C 只有裸指针，无引用与借用检查，需警惕越界与缓冲区溢出。
