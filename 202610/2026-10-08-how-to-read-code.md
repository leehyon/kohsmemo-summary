# How to read code
- URL: https://www.seangoedecke.com/how-to-read-code/
- Added: 2026-10-08 05:01:08

## TL;DR
读代码不应线性通读。应多轮、非线性扫描：先追关键路径与调用链，把其余当黑盒，最后端到端读 diff 抓异常。AI 生成代码仍须亲自读，因其常有对齐偏差，不能完全交给 LLM 审阅。

## Summary
文章指出，读代码不能像读书一样从头到尾顺序阅读：代码顺序主要由计算机执行决定，常以 diff 形式被阅读，且结构更复杂、规模更大。大型程序超出单人理解能力，因此读代码本质上是分配有限注意力的取舍过程。作者主张用多轮、非线性的 dyadic scanning 来读，并强调即使有 LLM 也必须亲自读代码。

**逻辑脉络**
- 先对比文本与代码：文本可任意排序、作为成品阅读；代码受运行约束、以 diff 为主、依赖可跨整个代码库、行数常达数十万。
- 再指出常见错误：顺序通读、只看 diff、被复杂度击败而猜测；原因是人脑容量有限。
- 提出方法：先选关键路径（如 diff 中的 happy path），追踪函数调用流；多轮扫描不同线程；对函数或数据查看所有调用点，包括 diff 外；用 ctrl+f 或 ctrl+click 导航；当前只关注一点，其余当黑盒。
- 最后确认理解后，再端到端读 diff，目的不是学结构，而是抓前几轮没注意的怪代码；发现异常就回到扫描。
- 反驳 AI 替代论：LLM 代码质量依语境而定，且会犯对齐错误，例如把无害竞态改成三千行复杂修复；LLM 审阅者的技术价值观未必与你或公司一致。

**Takeaways**
- 读代码要非线性：先结构后细节，多轮扫描，按调用链追踪。
- 选重要路径，把其余部分当黑盒，只在需要时展开。
- 最后端到端读 diff，专门捕捉异常点。
- AI 生成的代码仍须亲自读；常见问题不是 bug，而是对齐偏差。
- 可用 LLM 辅助，但必须审查其输出，不能外包判断权。
