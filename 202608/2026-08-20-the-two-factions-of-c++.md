# The two factions of C++
- URL: https://herecomesthemoon.net/2024/11/two-factions-of-cpp/
- Added: 2026-08-20 02:46:35
- Tags: #language

## TL;DR
文章分析 C++ 因向后兼容与安全需求之间的根本冲突而分裂为现代与遗留两大阵营，指出工具链和构建能力是分水岭，并解释了委员会在 Safety Profiles 等提案上的立场。

## Summary
C++ 社区正陷入分裂，文章将其归因于两个阵营的根本差异：现代 C++ 用户拥有良好工具链，能从版本化源代码构建，而遗留 C++ 用户则依赖老旧、不可构建的代码库。作者认为，C++ 标准委员会坚持向后兼容和 ABI 稳定，导致语言演进缓慢，迫使大型科技公司转向 Rust 或自研语言。

**逻辑脉络**
- C++ 的 EWG 通过 P3466，重申不破坏 ABI、保持向后兼容，并与零开销原则冲突。
- 美国政府和大型科技公司（如 Microsoft、Google、AWS）因内存安全担忧采用 Rust，Google 甚至降低参与 C++ 标准化的投入。
- 委员会以“不能要求用户修改 1% 代码”为由设计 Safety Profiles，但现代公司有能力通过自动化工具迁移。
- 作者提出两个阵营的分界线：是否能从版本化源码构建并拥有良好工具链，而非 C++ 版本本身。
- 委员会的设计（如 Profiles、Modules）优先考虑遗留代码，导致 Safe C++ 提案难以被采纳。

**Takeaways**
- C++ 的标准委员会与大型科技公司之间的信任正在流失。
- 现代 C++ 与遗留 C++ 的冲突是根本性的，且难以调和。
- 安全性与向后兼容的权衡使得 C++ 演进步履维艰。
- 工具链和构建能力是区分两个阵营的关键因素，而非语言特性。
