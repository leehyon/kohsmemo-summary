# Agent 插件如何走向工程化

- Added: 2026-08-10 06:31:34
- Tags: #engineering #agent

## TL;DR
Agent 插件工程化需把能力当软件资产：通过规格驱动、上下文编排、确定性验证、行为评测、证据闭环五个实践，确保插件可验证、可维护、可持续演进。核心是让每一次修改都有证据证明变得更好。

## Summary
Agent 插件工程化的核心不是把 SKILL.md 写得更复杂，而是将插件能力当作软件资产维护。文章基于 Better Harness 实践，提出规格驱动、上下文编排、确定性验证、行为评测和证据闭环五个环节，确保能力可验证、可维护、可持续演进。

**逻辑脉络**
- 从个人 Prompt 到插件生态，能力面临行为契约、变更验证、环境兼容、效果评估等软件工程问题。
- 规格驱动：将行为写成可验证契约，明确触发条件、上下文、禁止行为及验收条件，并引入多 Agent 评审。
- 上下文编排：采用渐进式披露，通过可发现、可到达、可追踪保证知识路由，让正确知识在正确时机进入上下文。
- 确定性验证：用静态检查、单元测试、契约测试守住可判定边界，例如验证 --help 路径不产生副作用。
- 行为评测：通过正例、负例、边界用例，观察 Agent 是否真正选择、读取、执行并产出可验证结果。
- 证据闭环：通过无 Skill、当前版本、候选版本三组对照，沿“存在→找得到→执行→有效”证据链判断，避免“路由但未执行”。

**Takeaways**
- 规格应约束可观察行为，而不是锁定具体措辞。
- 知识路由需自动测试验证链接与引用，文档图生成器辅助追踪。
- 能由程序判定的边界交给程序，模型负责理解、规划与权衡。
- 行为评测需关注选择、上下文、执行、结果四个方面，并重复运行以保证稳定性。
- Skill 演进应从证明改进效果开始，而非生成更多未经验证的 Skill。
