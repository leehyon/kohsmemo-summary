# SQLite for Everything
- URL: https://joecode.com/2026-08-19-sqlite3/
- Added: 2026-08-21 02:53:39

## TL;DR
本文主张 SQLite 可替代许多专用系统：搜索、文档、队列、时序、向量、缓存等，因它稳定、简单、快且内置于进程；多数场景无需独立服务，达到单机上限前应先用 SQLite。

## Summary
文章回应“PostgreSQL for Everything”，主张 SQLite 才是许多场景的更优选择。作者认为 SQLite 的威力来自三点：稳定可靠、极易运行与扩展、能大幅简化 IT 架构。

**逻辑脉络**
- 作者先对比 SQLite 与 PostgreSQL 的定位，指出 SQLite 是公共领域、测试严苛、支持至 2050 年的“无聊”技术。
- 接着逐一论证 SQLite 可替代全文搜索、文档存储、消息队列、时序数据库、向量数据库、缓存、文件系统、图数据库甚至微服务。
- 最后以 Mandelbrot 等示例收尾，强调其灵活性。

**底层逻辑**
- 核心假设是：能用一个文件加函数调用完成的事，就不应引入独立服务。
- SQLite 没有网络开销，事务与搜索索引同步更新，因此更简单、更快、更可靠。
- 作者也承认单写入者与单机上限，但认为多数场景远未触及。

**Takeaways**
- SQLite 稳定性极强：公共领域、2050 年支持承诺、MC/DC 100% 分支覆盖。
- 运行与测试成本低：内置于 OS 与语言，:memory: 即可做并行测试，无需容器。
- 可替代多种专用系统：FTS5、JSON 与 jsonb、队列表、时序分区、sqlite-vec 向量检索、缓存等。
- 性能反直觉：小 blob 读写比文件系统快，内存点查快于 Redis，批量插入每秒数十万行。
- 适用边界：单写者、单机；达上限时再换 PostgreSQL 等，但多数项目不必提前引入。
