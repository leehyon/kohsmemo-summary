# Human judgment doesn't leave the software factory
- URL: https://addyosmani.com/blog/human-judgment-doesnt-leave-the-software/
- Added: 2026-08-31 02:06:13
- Tags: #agent

## TL;DR
文章指出软件工厂不会取代人类判断，而是将其重新定位到产品意图、质量与风险控制。验证机制建立信任，决定自主性，人类仍需最终拥有发布责任。

## Summary
文章围绕“软件工厂”中人类判断的地位展开，核心观点是自动化不会让人类离开循环，而是将判断重新定位到意图、设计与质量门槛。作者结合个人实践经验，提出验证机制是获得信任、决定自主性的关键。

**逻辑脉络**
- 从定义软件工厂为“围绕软件工作的可重复循环”开始，说明在简单场景下使用 Claude Code 或 Codex 即可，只有需要事件驱动、重复执行时才应搭建工厂。
- 通过个人并行工作案例，指出认知带宽无法随代理数量扩展，必须把人类品味编码进环境。
- 以 82 分钟工厂运行实例说明验证能发现真实问题，并讨论运行状态分类与阶段耗时。
- 最后强调人类所有权不消失，而是被重新布置。

**底层逻辑**
- 核心假设是代码可由机器大量生成，但人类判断是稀缺资源。
- 工厂应将确定性信号自动化，将人类注意力集中于风险、品味与长期责任。
- 验证换取信任，信任决定可授予的自主性，因此约束应随信任变化而刻意调整。

**Takeaways**
- 先判断是否真需要工厂，简单任务用现有工具与明确 SPEC 可能就足够。
- 设立验证预算：快速检查（lint、类型）前置，重型检查（测试、安全）在合并前运行，追求信噪比。
- 用“成功、缺陷、阻塞、手动”分类运行结果，并记录每阶段耗时，让成本可见。
- 并行工作会带来认知债务，可让代理记录轨迹与决策原因，供日后回溯。
- 人类需拥有最终发布责任，并集中在风险最高处，“代理写的”不能成为免责理由。
