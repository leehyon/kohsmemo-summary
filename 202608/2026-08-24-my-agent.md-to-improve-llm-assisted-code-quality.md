## TL;DR
作者通过创建 agent.md 文件，将代码风格偏好固化到 LLM 提示中，显著提升生成代码的可维护性，并分享应对上下文稀释的方法。

## Summary
本文介绍作者通过创建 agent.md 文件来系统性地提升 LLM 生成代码的质量，并分享具体规则与应对上下文稀释的方法。作者强调 agent.md 能显著改善代码风格，但无法替代人工审查。

**逻辑脉络**：
- 2025 年中期首次尝试 LLM 编码，效果差，代码无法编译。
- 2026 年 1 月重试，功能实现但代码质量低劣（无注释、结构混乱）。
- 2026 年 3 月使用 agentic IDE（如 Antigravity、Claude Code），通过反复提示改进，但重复劳动多。
- 将重复建议固化到 agent.md，随会话注入提示，效果显著。
- 上下文稀释会降低指令遵从度，需缩短上下文或显式重载 agent.md。

**Takeaways**：
- 将代码风格规则写入 agent.md，可减少跨会话的重复提示。
- 规则示例：避免魔法数、函数名 < 30 字符、用枚举而非布尔参数、减少缩进、加空行和注释等。
- 提交信息遵循 7 条规则（主题 ≤ 50 字符、祈使语气、正文解释 why 等）。
- 修复 bug 时先写失败测试，再写修复，验证通过。
- agent.md 非万能药，仍需人工审查，但可聚焦架构设计。
- 应对上下文稀释：每功能开新会话，或提示 "Reload agent.md"。
