# 我和 AI 共创了一套会自己生长的 Obsidian 知识库
- URL: https://zxs.io/article/2215
- Added: 2026-08-25 01:30:06
- Tags: #note-taking #agent

## TL;DR
作者用 Obsidian + Claude Code 搭建了一套由 AI 持续维护的知识库，通过收录、查问、体检三个流程让笔记自动更新、关联和质检，并用 CLAUDE.md 规范 AI 行为，最终实现从找资料到用知识的转变。

## Summary
作者从 Notion 转到 Obsidian，与 AI 共创一套会持续生长的知识库。核心不是换工具，而是让 LLM 直接读写本地 Markdown 笔记，替代只读式 RAG，实现知识累积、矛盾发现和自动关联。

**逻辑脉络**
- 从 Notion 的痛点出发：笔记记了没人看、找不到、无结论记录。
- RAG 的局限：知识不累积、矛盾不被发现、源材料不连接。
- 受 Karpathy 的 LLM wiki 启发，让 AI 维护笔记：读原文、写结构化笔记、更新旧笔记、矛盾校验、补 wikilink。
- 日常三件事：收录（读来源、摘要、更新实体页、补链、矛盾校验）、查问（读已维护笔记生成答案，可归档）、体检（查矛盾、孤岛、过期、重复，不擅自删除）。
- 用 CLAUDE.md 作为 AI 的员工手册，定义 vault 身份、目录职责、安全边界、笔记类型、工作流程。
- 工具链：Obsidian 为操作系统，Claude Code 为执行器，Skill 固化流程，graphify 发现关联，wiki-relate 写回笔记。
- 避免退化的五个坑：不什么都收、不追求完美结构、限制 AI 边界、持续迭代 CLAUDE.md、每日小维护。

**底层逻辑**
- 第一性原理：LLM 能读写文件，因此能直接操作系统中的笔记原文，而非向量片段。
- 知识库的价值在用，不在看；维护是重复劳动，应交给 AI，人只做判断。
- 规则显式化：CLAUDE.md 让 AI 行为可预测、可复现。
- 先存在再变好，通过持续小步改进积累复利。

**Takeaways**
- 从只读 RAG 转向 AI 持续维护：让笔记自己更新、自己记账、自己质检。
- 日常只需三件事：收录、查问、体检，分别对应知识的进入、使用和健康检查。
- CLAUDE.md 是全局约束层，把目录、安全边界、类型系统和工作流写清楚，AI 才能稳定执行。
- 工具少而专：Obsidian + Claude Code + Skill + graphify/wiki-relate 各司其职。
- 防止退化：只收能回答问题的内容，限制 AI 删除/放图，每天 10 分钟比突击一天更有效。
