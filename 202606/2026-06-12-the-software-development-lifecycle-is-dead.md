# The Software Development Lifecycle Is Dead
- URL: https://boristane.com/blog/the-software-development-lifecycle-is-dead/
- Added: 2026-06-12 02:34:14
- Tags: #engineering #view

## TL;DR
AI agent 没有加速 SDLC，而是使其崩溃。传统阶段合并为意图-构建-观察循环。上下文工程和可观测性闭环成为核心，大多数行业尚未适应。

## Summary
AI agent 没有加速传统的软件开发生命周期（SDLC），而是使其各阶段合并甚至消失。传统的需求、设计、实现、测试、代码审查、部署、监控等阶段被一个紧密的“意图-构建-观察”循环取代。核心技能从过程管理转向上下文工程，监控成为最后的安全机制，但必须从面向人类仪表盘进化为 agent 的闭环反馈回路。

**逻辑脉络**
- 传统 SDLC 是线性、离散的阶段，每个阶段有独立工具和仪式（如 Jira、Figma、VS Code、Jest、GitHub、AWS、Datadog）。
- AI agent 让阶段不再分立：需求成为迭代产物，设计在交互中实时发现，实现由 agent 完成，测试与代码同时生成，代码审查需要重新思考——agent 自验证或对抗验证取代人工 PR 流程。
- 部署由 agent 自动化且解耦（持续部署与发布分离），监控成为反馈核心，但必须从人工告警仪表盘进化为 agent 直接使用的闭环系统。
- 新循环只有三步：意图 → 构建 → 观察 → 重复。没有门票、迭代、故事点、PR 队列、独立 QA 阶段或发布火车。
- 剩余的关键是给 agent 的上下文质量和可观测性基础设施。传统工具如 Jira 已不适配，它本应是为跨阶段协调设计的，但现在只是糟糕的上下文集。

**Takeaways**
- 传统 SDLC 各阶段已合并或消失，新工作流是紧密循环，不再有手写代码和等待。
- 代码审查作为人类仪式需要淘汰，转向 agent 自验证或对抗验证，人类只在异常时介入。
- 监控成为最后安全机制，但必须从面向人类仪表盘进化为 agent 的反馈回路，否则会变成新瓶颈。
- 上下文工程成为新核心技能：输出质量直接取决于输入上下文的准确性、完整性和质量。
- 大多数团队仍在配置无人查看的仪表盘，未意识到变革；最早实现可观测性闭环反馈的团队将获得竞争优势。
