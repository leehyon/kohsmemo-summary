## TL;DR
使用 AI Agent 编程需转型为管理者：定义目标、审查结果，将执行交给 Agent，验证交给工具链。核心原则包括精力管理、工程管理、快速反馈和保持代码简单可控。

## Summary
使用 AI Agent 编程需要转变角色，从逐行编码的工程师变为定义目标、划定边界、审查结果的 Manager。关键挑战是精力管理，必须通过使用最强模型、写详细的 Prompt、先计划再构建、保持可逆沙盒等策略来降低决策成本。同时，工程管理、快速反馈和保持代码简单可控是保障产品质量的核心。

**底层逻辑**
- 作者的第一性原理是：AI 时代信息爆炸，人的精力是最大瓶颈，因此一切操作应围绕降低决策成本、提升信息信噪比展开。核心假设包括：更贵的模型能减少干预；Prompt 是临时规格说明；所有工程工作应先用 Plan Mode 澄清需求；Agent 应工作在可逆沙盒中，并配合版本控制和小步快跑；强静态类型语言和快速反馈环路能提升协作效率。

**Takeaways**
- **精力管理**：使用当前最贵的模型（如 Claude Opus）进行开发，以降低管理成本；写包含背景、目标、非目标、修改范围、验收标准、验证命令和风险边界的 Prompt；所有工程工作先使用 Plan Mode 讨论，避免需求模糊；对低风险细节降低审查强度，对数据、权限、计费等高风险改动重点审查。
- **工程管理**：始终使用版本控制并远程备份，让 Agent 工作在独立 branch 或 worktree 中；以功能为单位小步快跑；禁止 Agent 直接操作生产环境，必要时生成操作手册并人工执行。
- **快速反馈**：优先使用强静态类型语言以提供早期反馈；构建包括 Type Check、Lint、Format、Testing 和 Cyclomatic Complexity 的反馈回路，并利用 git hook 和 CI/CD 自动化；CI 阻止不合格代码入主分支，CD 确保可审计回滚的发布。
- **代码是你的**：保持代码简单易理解，避免复杂写法；跑 Cyclomatic Complexity 检查，超标重构；确保自己始终能接管项目。
