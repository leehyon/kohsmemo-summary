# 关于 Vibe Coding 如何提升代码效率和质量的技巧之 Skill

## TL;DR
本文教你如何编写个性化 skill 规则文档，通过显化工程判断、按需加载、强制执行，使 AI 稳定生产可靠代码。核心：skill 与 CLAUDE.md 分工、按职责拆分、三条灵魂规则（穷举边界、自审、重构决策）及持续更新。

## Summary
本文系统阐述了如何通过编写个性化 skill 规则文档，将隐性工程判断显性化，使 AI 持续产出可靠、可上线的代码，而非依赖一次性 prompt。核心在于把“什么叫写对”的标准固化为 AI 每次必读的规则，并通过强制加载机制确保执行。

**底层逻辑**
- AI 代码不可靠的根本原因不是模型能力不足，而是缺乏对开发者特有标准的认知与遵循机制。skill 的作用是将这些标准文档化、持久化，并利用触发词和路由表实现按需精准加载，避免上下文膨胀。
- 通过全局 CLAUDE.md 强制加载指令，堵住 AI 自行跳过的漏洞，保证规则被真正执行。

**Takeaways**
- 区分 CLAUDE.md 与 skill：CLAUDE.md 记录项目快照，skill 固化个人方法论，互不替代。
- skill 结构：顶层 SKILL.md（含触发词 + 路由表）+ references/ 目录（按职责拆分，每文件一个领域），避免长上下文。
- 三条必装灵魂规则：动手前穷举输入/状态/流程分叉等边界，动手后走完九条自审，每次非平凡改动做幅度评估（倾向重构而非打补丁）。
- 强制加载机制：在全局 CLAUDE.md 中显式要求涉及代码/项目/配置的任务必须加载 skill，并明确定义例外与兜底。
- 持续迭代：每遇新坑即记录进对应 references 文件，让 skill 成为复利资产，避免重复犯错。
