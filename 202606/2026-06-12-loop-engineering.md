# Loop Engineering

- Added: 2026-06-12 03:07:14
- Tags: #engineering

## TL;DR
循环工程是用系统自动提示代理代替手动提示。设计包含自动化、工作树、技能、插件、子代理和持久状态的循环，可提升效率但需警惕验证、理解和认知风险。

## Summary
Loop engineering 将手动提示编码代理的方式转变为设计自动提示代理的系统。通过定义递归目标并让 AI 迭代直至完成，它可能成为与编码代理协作的未来。但需谨慎处理 token 成本。

**逻辑脉络**
- 文章从专家观点切入：Steinberger 和 Cherny 主张不再手动提示，而是设计循环。解释过去两年手动提示的局限，引出循环工程的概念。
- 分解循环所需的五个要素（自动化、工作树、技能、插件/连接器、子代理）和状态（记忆），并对比 Codex 和 Claude Code 的实现。
- 给出一个实例：自动化每日运行，技能执行分类，子代理分写和校验，连接器操作 PR/ticket，状态文件跟踪进展。
- 指出循环的局限：验证仍需人工，理解可能退化，舒适姿势（认知投降）的危险。

**Takeaways**
- 设计循环代替手动提示：用自动化发现任务，技能固化知识，子代理分工（创造者 vs 检查者），工作树隔离并行。
- 将状态持久化到模型外（如 markdown 文件），克服模型遗忘。
- 警惕 token 成本、验证责任和认知投降；保持工程师角色，平衡自动与手动提示。
- 循环本身是中性的，结果取决于使用者：深入理解者加速，逃避理解者恶化。
