# Just Talk To It - the no-bs Way of Agentic Engineering
- URL: https://steipete.me/posts/just-talk-to-it
- Added: 2026-06-30 07:03:03
- Tags: #agent #workflow

## TL;DR
作者主张直接与 AI 编码代理对话（Just Talk to It），推荐 codex CLI，反对复杂框架，强调通过自然语言、截图、并行代理和迭代而非规范驱动来高效开发软件。

## Summary
作者通过自身实践，提出在当前的智能水平下，最有效的代理工程方法是直接与模型对话（Just Talk to It），而非构建复杂的框架、RAG、子代理或繁琐的提示工程。他详细对比了 codex CLI 与 Claude Code，认为 codex 在速度、上下文效率、语言风格上更优，并分享了其工作流程：并行运行多个代理、原子提交、用截图替代长篇提示、避免过度工程化工具（如 MCP、规范驱动开发）。文章强调应培养与模型协作的直觉，信任模型并迭代。

- **逻辑脉络**：
  - 从个人项目背景（300k LOC TypeScript 应用）出发，说明已完全迁移到 codex CLI，并行运行 3-8 个代理。
  - 比较 codex 与 Claude Code：codex 更高效（230k 上下文 vs 156k）、更便宜（订阅制）、更少废话、更快、更稳定的终端体验。
  - 批判性地分析其他工具：amp 依赖 GPT-5 作为“oracle”但实际不如直接使用 codex；Cursor 的补全模型虽好但 bug 多；MCP 常为上下文垃圾，应优先使用 CLI。
  - 提出工作流关键：“爆炸半径”概念——分小批次修改以避免混乱；通过 tmux 处理后台任务；用截图而非长文本提示；用消息队列让模型自主完成多步骤任务。
  - 反对规范驱动开发：认为设计完整规范再让模型执行是旧思维，更优的方式是与模型讨论、迭代，让模型参与设计过程。
  - 代理文件（Agent.md）应简洁，包含组织需求和模式说明，而非威胁性语言。

- **底层逻辑**：
  - 核心假设是当前模型（尤其是 GPT-5-codex）的智能水平已足够高，能够理解上下文、自主探索代码库并做出正确决策。复杂的工程化包装（子代理、MCP、RAG）反而引入不必要的成本和精神负担。
  - 作者信任模型的能力，认为“just talk to it”不仅是口号，更是基于模型正面交互的实践哲学：减少间接层，让沟通更直接。

- **Takeaways**：
  - 直接与模型对话：使用自然语言、截图或简短提示，避免过度包装。
  - 并行处理任务：在多个终端中运行独立的 codex 代理，每个处理一个原子变更，提交隔离。
  - 选择 codex 而非 Claude：更快的速度、更大的有效上下文、更少 token 浪费、更尊重开发者的语言风格。
  - 避免过度工程化：优先使用 CLI 而非 MCP，用 tmux 而非子代理，迭代而非规范驱动。
  - 培养直觉：观察代理行为，适时打断、重新引导或继续，20% 时间用于重构以保持代码质量。
