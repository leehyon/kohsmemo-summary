# node_modules 为什么总是这么大

## TL;DR
node_modules 体积大的根源是开发环境重复存储，而非业务代码。使用 pnpm 通过全局 store 共享依赖，可显著节省磁盘空间并提升依赖管理严格性。

## Summary
node_modules 体积膨胀的主要原因是开发环境依赖（TypeScript、构建工具、运行时等）重复存储，而非业务代码本身。通过迁移至 pnpm，借助内容寻址存储和硬链接，可显著减少磁盘占用。

**逻辑脉络**：
- 膨胀原因包括依赖树深、多项目重复存储、版本不一致及小文件碎片。
- 真实案例：主项目 262M、worker 169M、website 147M，大头均为开发工具链（TypeScript、esbuild、Cloudflare 运行时等），业务代码仅几百 KB。
- 传统方法（rm 重装、npm dedupe、少装包）治标不治本。
- pnpm 通过全局 store 和链接机制实现跨项目共享依赖，并严格限制隐式依赖。
- 迁移实践：新项目直接 pnpm，老项目删 node_modules 后 pnpm install；统一锁文件；CI 用 --frozen-lockfile。
- 坑：老项目可能依赖隐式提升，可设 nodeLinker=hoisted；需团队统一管理器。

**Takeaways**：
- 空间痛点不在 src，而在构建链、运行时、类型定义等开发依赖。
- pnpm 在多项目环境下节省磁盘效果显著，且安装更快。
- 依赖关系更严格，能提前发现隐式依赖问题。
- 迁移需清理旧锁文件，并确保 CI 环境一致。
- 紧急清理时，优先删除不活跃子项目的 node_modules。
