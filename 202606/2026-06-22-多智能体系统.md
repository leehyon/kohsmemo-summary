## TL;DR
本文系统介绍了从单智能体 ReAct 到多智能体多种架构模式（LangGraph 与 LangChain 定义），对比了性能与适用场景，并探讨了分布式智能体的协议与挑战。

## Summary
多智能体系统通过分工协作突破单智能体在上下文管理、分布式开发和并行化方面的瓶颈。本文系统梳理了从单智能体 ReAct 框架到多智能体多种架构模式（LangGraph 与 LangChain 定义）的设计思路，并分析了分布式智能体的协议与挑战。

**逻辑脉络**
- 单智能体 ReAct 框架通过推理 - 行动 - 观测循环实现任务解决，但面对复杂任务时存在上下文限制和可扩展性差的问题。
- 多智能体引入上下文管理、分布式开发与并行化能力。Anthropic 研究表明，恰当的多智能体系统比单智能体高出 90.2% 的性能。
- LangGraph 将多智能体模式分为网络、监督、工具化监督、层级和自定义五种，并对比了优缺点与适用场景。
- LangChain 则提出子智能体、技能、路由、传递和自定义五种模式，从分布式开发、并行化、多跳调用和用户直接交互四个维度进行对比，并给出调用次数与 token 消耗的定量分析。
- 实际系统实现如 OpenClaw（子智能体模式）、Hermes Agent（路由模式）、QwenPaw（路由模式）展示了不同选择。
- 分布式智能体通过 A2A 协议实现异构协同，但面临状态一致性、调度容错和消息效率等挑战。

**Takeaways**
- 优先从单智能体开始，仅在触及上下文或性能瓶颈时引入多智能体。
- 模式选择取决于场景：子智能体模式适合中心化调度，路由模式适合并行查询，传递模式适合顺序对话。
- 技能模式作为“准多智能体”提供轻量级专业化，不管理独立智能体实例。
- 分布式智能体依赖标准化协议（如 A2A），但需解决任务状态一致性与容错问题。
