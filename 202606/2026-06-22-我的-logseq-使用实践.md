## TL;DR
本文总结 Logseq 使用实践，涵盖同步、笔记方法、工作流构建，强调方法论比工具重要，建议从 Journal 入门，用 Query 进阶，定期回顾并输出文章。

## Summary
作者分享 Logseq 使用经验，强调方法论比工具重要，入门从 Journal 开始，高阶用 Query 工作流。文章从同步、笔记方法、工作流构建等方面展开，最后指出双链并非核心，写文章才能真正连接知识。

**逻辑脉络**
- 同步问题：避免官方同步数据丢失，使用第三方网盘单向同步，多设备手动复制。
- Journal vs Page：Journal 记录零散片段，Page 组织整合（Capture vs Organize）。
- 记录内容：外部来源（高亮、引用、书签等）和内部来源（故事、洞见、反思等）。
- 时间登记：用 Markdown 时间块记录任务，便于追踪。
- 定期回顾：对抗遗忘曲线，推动知识内化，遇见过去的自己。
- 卡片笔记工作流：用模板标准化，Query 提示下一步，分闪念笔记、文献笔记、永久笔记。
- PARA 实践：将信息分为 Projects、Areas、Resources、Archives，推动项目进展。
- 双链反思：真正连接知识的是写文章，而非双向链接。

**底层逻辑**
- 工具不重要，底层方法论（卡片盒笔记法、PARA）才是核心。
- 通过持续学习和输出构建知识体系，边界随好奇心延伸。

**Takeaways**
- 同步：官方同步不稳定，推荐第三方网盘单向同步。
- Journal 与 Page：Journal 记录灵感，Page 整合成文。
- 记录内容：外部高亮与内部感悟同等重要。
- 定期回顾：提升笔记价值，促进自我审视。
- 卡片笔记工作流：模板 + Query 实现自动化流程。
- 不要神话双链：写文章才是知识串联的关键。
