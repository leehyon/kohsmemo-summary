# Default blind

## TL;DR
“默认盲”指软件业务中因缺乏自动观察而对状态无知，对比实体店。观察是 OODA 循环第一步，易被忽视导致迷失方向。组织需识别定向者、主动学习业务并设定团队期望。

## Summary
- 核心主题：“默认盲”指软件业务中因缺乏自动观察而对企业状态无知，与实体业务形成对比。
- 关键信息：
  - 实体店自然观察顾客行为（如春节买红纸），软件业务需主动设置查询（如 SQL 仪表盘），默认无信息。
  - OODA 循环中“观察”是首要步骤，软件中决定与行动不难，难在观察与定向。
  - 人们容易忘记观察，自动生成假设（如将销售增长归因于返校），混淆假设与真实模型。
  - 迷失方向的表现：缺乏基本概念（如“什么是 LTV”）、无法语境化指标（如“2000 件商品算多吗”）、不能解释事件（如“合作方推出新品意味着什么”）。
- 逻辑脉络：
  - 从个体案例引出“默认盲”概念，对比实体与抽象系统。
  - 分析为何软件业务中难以观察，以及迷失如何长期持续（紧急任务循环、缺乏数据验证）。
  - 扩展到组织层面：50% 人员迷失时仍可维持（有定向者指引），80% 迷失时系统崩溃（多数会议无意义、定向者离开）。
  - 最后给出应对建议：识别定向者（常被提问、提供证据如 SQL）、个人主动学习业务（记录指标关系、批判接收信息）、设定团队期望（长期迷失者应离开）。
